# Title

User documentation (README, references, CI recipe)

## Summary

Write the user-facing docs: a README that sells and teaches the tool in ten minutes, a complete
config + step-DSL reference generated-by-hand from DESIGN §6–§8, a CI recipe (GitHub Actions
YAML for `check`/`coverage` and a scheduled refresh PR pattern), and a troubleshooting guide —
in English, accurate to the implemented behavior.

## Context

v1 targets public OSS adoption (Q10): documentation quality is a launch feature. The README must
lead with the docs-coverage differentiator (ADR-001), not generic screenshot automation. The CI
recipe replaces the deferred GitHub Action (Q8).

## Scope

- `README.md` (replaces the 2-line placeholder), `docs/reference/configuration.md`,
  `docs/reference/steps.md`, `docs/reference/ci.md`, `docs/reference/troubleshooting.md`.
- English. No code changes (docs-only; text must match implemented behavior exactly).

## Detailed Requirements

1. `README.md` sections, in order: value proposition (docs screenshots rot → freshness +
   coverage, 3 sentences); animated-free quickstart (init → config 10 lines → update → embed);
   how the diff gate works (1 short section, link ADR-005 concept); coverage section with a
   sample report; CI usage teaser linking `docs/reference/ci.md`; security model summary
   (trust model: config/hooks are code; origin allow-list; no secrets in v1; the explicit
   §17.5 warnings — never type real credentials via `fill`, screenshots of real data are a
   leak vector, use masks and seeded/demo data — link SECURITY.md); comparison table (one paragraph + table vs shot-scraper / doc-detective /
   visual-regression tools, sourced from `docs/research/competitive-landscape.md`, factual and
   respectful); requirements (Node ≥ 20, `npx playwright install chromium`); license.
2. `configuration.md`: every key from DESIGN §6.2 with type, default, constraints, and one
   example each; the semantic rules table (§6.3) rendered for users; three complete example
   configs (static site, dev-server command, external URL).
3. `steps.md`: per-step section with both YAML forms, defaults, failure behavior, and one
   realistic example; the `fill` section repeats the §17.5 credential warning; hooks section
   (contract, `ctx` fields, timeout, trust warning from ADR-003); a worked "open modal and
   capture element" recipe.
4. `ci.md`: copy-pasteable workflows — (a) PR gate: `check` + `coverage --fail-on broken,unmanaged` (DESIGN §3.4);
   (b) scheduled refresh: cron `update` + `peter-evans/create-pull-request`-style PR (SHA-pinned,
   least-privilege `permissions:` blocks, cache for npm + Playwright browsers); notes on
   diff-artifact upload for review.
5. `troubleshooting.md`: the top failure modes with exact error codes and fixes —
   `BROWSER_NOT_INSTALLED`, `SERVER_START_TIMEOUT` (readyPath, logs), `NAV_BLOCKED_ORIGIN`
   (allowedOrigins), flaky diffs (masks, seedRandom, freezeTime, settleMs), `CONFIG_PATH_ESCAPE`
   meaning, exit-code table (§14.4).
6. Every CLI transcript in docs is generated by actually running the built CLI
   (`npm run build && node dist/cli/main.js <args>`) against a temp copy of
   `tests/fixtures/e2e-app/` and pasted verbatim, preceded by an HTML comment of the form
   `<!-- source: <command>; cwd: temp copy of tests/fixtures/e2e-app -->` — no invented output.
7. Cross-check step: a checklist in the PR description mapping each documented flag/key/step to
   the implementing issue, confirming no doc mentions unimplemented behavior (e.g. no `--force`
   on `check`).

## Acceptance Criteria

- [ ] All five files exist with the sections above; README leads with coverage differentiation.
- [ ] Config reference covers 100 % of §6.2 keys (scripted check against the zod schema key
      list, run once and pasted into the PR).
- [ ] Steps reference covers all 10 step types + hooks.
- [ ] CI workflows are valid YAML, SHA-pinned, with explicit `permissions:` blocks.
- [ ] All CLI transcripts reproduce against the e2e fixture (spot-checked in review).
- [ ] No documented feature is unimplemented; no implemented command/flag is undocumented
      (checklist complete).
- [ ] Language: English throughout; competitor comparison contains no unverifiable claims.

## Validation

- Docs-only PR reviewed against the checklist; `markdownlint`-style formatting is NOT enforced
  (Biome doesn't lint MD) — a human read-through is the gate.

- CHANGELOG (issue 28).
